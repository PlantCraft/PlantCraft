# Gaps

> **Updated:** 2026-10-20

Every known shortfall of PlantCraft Analytics, ranked by user impact. `B` marks a blocker for the next stage.
When a gap closes, delete its row in the same change and note it in `CHANGELOG.md`. Ids continue the
monolith's numbering for the PlantCraft Analytics rows (G1, G3).

| G28 | `stiction_screening` reads only the OP pattern (stuck moves, and jumps right after a stuck move); it has no PV-OP shape test (Horch's cross-correlation, the PV-OP ellipse or the bicoherence test of Choudhury 2006), so stiction behind a smooth controller output is not recognised. Downgraded 2026-10-19: the false alarms on a saturated OP and on a tuning oscillation are fixed (saturated spans left out; jumps count only after a stick). Horch's test was not added because it assumes OP is the controller output, while the screen treats OP as the valve movement: on `tests/plant.py` FIC-105 (OP in phase with PV) it would call the stick-slip "no stiction"; adding it needs the valve-position input or a per-loop choice of what OP is | medium | |
| G29 | No method separates an oscillation caused by an external disturbance from one caused by aggressive tuning; both oracle cases are only "oscillation" | medium | |
| G37 | On the 50-loop simulator scenario the stiction (82-94) and sensor-drift (89-93) loops score like healthy ones (80-91): the error stays small in both (MAE 0.3-0.7 % of SP), the stiction screen is a diagnostic outside the score by design and flags only one of the four (the simulator's valve has no slip, G30), and no method looks for a drifting sensor that the controller holds at SP (it needs a second measurement or a mass balance). Also, `op_travel_reversal` reports "bad" on the healthy temperature and level loops (simulated OP noise against the 100 %/h allowance of those types); it is outside the score | medium | |
| G36 | `error_metrics_basic` scales its tolerance to the PV span only when a person sets `pv_span`; PlantCraft keeps no signal ranges yet (`low`/`high` are null), so the default is 4 % of the median setpoint, which is too strict near zero (a setpoint below about 1 % of the span) and falls back to the absolute 1.0 at a zero setpoint. Read the span from PlantCraft once it keeps engineering ranges | medium | |
| G38 | PlantCraft's loop record says what a level controls, not whether it is held tight or averaged inside a band, so every level starts on the Level loop protocol (tight) and an averaging level must be switched to the surge-level protocol by hand, or it loses points for using its band.
